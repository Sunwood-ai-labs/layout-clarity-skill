# Concrete transformations

## Project list

Before: `Workspace overview` / `Your projects` / `Manage all your projects in one place` / `Projects` / project cards / `Click here to create a new project`.

After: `Projects` + `New project` beside the heading, followed by the list. Keep ownership and status on each item when they affect selection. The heading and button placement explain the scope without a slogan.

## Form

Before: `Email address`, placeholder `Enter your email address here`, helper `Please type your email address into the field above`.

After: persistent visible label `Email address`; optional example placeholder. Remove the tautological helper. Keep `Use your work email to join your organization` when this is an actual requirement; keep a specific invalid-address error and correction.

## Dashboard metric

Before: `Revenue insights` / `Total revenue` / `$42,100` / `Here you can see your total revenue`.

After: `Revenue` / `$42,100` / `October · USD · excluding refunds`. Remove the narrative, not the measurement scope. Put a real comparison near the value if it exists; do not invent one.

## Destructive action

Before: `Delete project` and a paragraph saying that this button deletes the project.

After: precise `Delete project` action, with the actual irreversible consequences and affected object shown before confirmation. Never replace the confirmation with an unlabeled trash icon to save space.

## Empty state

Before: `Your journey starts here. Unlock your potential and experience productivity.`

After: `No projects yet` + `New project`. Keep a one-line prerequisite if creation requires permission or imported data. A useful empty state explains why nothing is present and how to proceed.

## Unfamiliar workflow

If users must choose between a snapshot and a synchronized copy, short explanatory text may be essential. Use a concise comparison near the choice. Do not assume spacing can convey a technical distinction that users have not learned.
